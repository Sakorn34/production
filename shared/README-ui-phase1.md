## ตัดสินใจ "ไม่ทำ" — ปุ่มเลิกทำ (undo) ของ 1.2

สเปคออกแบบให้เก็บสิ่งที่ลบไว้ใน session 30 วินาที แล้วมี `undo.php` เขียนคืน
**ตัดสินใจไม่ทำ (5 ก.ย. 2569)** เพราะความเสี่ยงไม่คุ้มกับสิ่งที่ได้ — กล่องยืนยัน
แก้ปัญหาต้นทางไปแล้ว (เห็นผลกระทบก่อนกด จึงลบผิดน้อยลง)

เหตุผลที่ต้องรู้ก่อนคิดจะทำใหม่:

1. **ลบข้ามฐาน** — `StockService::deleteStockOut()` ลบ `stock_out` +
   `stock_out_items` ใน `biton_tech_parts` (มี transaction) แล้วลบ
   `part_movements` ใน `biton_production` (อยู่นอก transaction คนละ connection)
   คืนสำเร็จข้างเดียว = ข้อมูลครึ่งใบ แย่กว่าลบไปเลย
2. **ต้องคืน id เดิม** — `part_movements.tech_stock_out_id` ชี้ `stock_out.id`
   ตรง ๆ (ผูกครบ 1,344/1,344 แถว) ปล่อย AUTO_INCREMENT ใหม่ = ลิงก์ขาด
   และระหว่างรอ undo อาจมีคนสร้างใบใหม่กินเลขนั้นไปแล้ว
3. **ลบอะไหล่กวาดของอื่น** — `products.php` เมื่อ FK ไม่ผ่านจะบังคับลบ
   `stock_out_items`, `stock_in`, `set_items` ต่อ · undo หนึ่งครั้งจึงต้องคืน
   ประวัติทั้งหมดให้ครบและถูกลำดับ
4. **ยอดขยับระหว่างรอ** — undo คืนของด้วย `quantity + N` แต่คนอื่นอาจเบิก
   ตัวเดียวกันไปแล้วในช่วงนั้น

ถ้าจะทำจริง **ให้ทำเป็น soft delete** (`deleted_at`) ไม่ใช่ insert กลับ —
undo กลายเป็นการเซ็ตค่าเป็น NULL id ไม่ชน ข้ามฐานไม่พัง แลกกับต้องเติม
`WHERE deleted_at IS NULL` ทุก query ที่อ่านตารางนั้น
