ข้อสรุปทิศทางการแก้ (แนะนำ)

  • ให้ parts รับธีมจากระบบหลัก — ระบบหลักมี appearance.php ที่ปรับสี/ฟอนต์ได้อยู่แล้ว ให้ parts อ่านค่าเดียวกัน (หรือ copy ชุดตัวแปร CSS เดียวกัน) จะได้เปลี่ยนธีมครั้งเดียวแล้วตรงกันทั้ง 2 ระบบ
  • ยกระบบ token ของ parts มาใช้ทั้งคู่ — parts มีโครง token ที่ดีกว่า (shadow/radius/transition) ให้ finishgoogs รับโครงนี้ไปใช้ แล้วเติมสีจากธีมลงไป
  • เลิกใช้ emoji เป็นไอคอนเมนู → ใช้ SVG ชุดเดียว — emoji แสดงผลต่างกันตามเครื่อง/เบราว์เซอร์ คุมสีไม่ได้ และตอนนี้ 2 ระบบใช้คนละชุด
  • ล็อกฟอนต์ไทยตัวเดียวกัน (Noto Sans Thai ตามที่ตั้งไว้ใน appearance.php) และ scale ตัวอักษรชุดเดียว: body 15px · h1 22px

#ปัญหาตำแหน่งระดับ
P1ไม่รับธีมจากระบบหลัก — สี/ฟอนต์ fix ตายใน style.css เปลี่ยนธีมที่ appearance.php แล้ว parts ไม่เปลี่ยนตาม ทั้งที่ตอนนี้ข้อมูล sync ถึงกันแล้วassets/style.css (:root)สูง
P2ไม่มีฟอนต์ไทย — Segoe UI แสดงไทยได้แต่ไม่สวย/ไม่ตรงกับระบบหลัก (ดู 1.2)includes/header.phpสูง

P4h1 26.4px ใหญ่กว่าระบบหลักมาก — และ body 16px vs 15px ทำให้ความหนาแน่นข้อมูล (density) ของตาราง 2 ระบบต่างกันassets/style.cssกลาง
P5ชื่อระบบใน sidebar คนละภาษา — "ระบบจัดการสต็อก" (ไทย) vs "Production" (อังกฤษ) ของระบบหลัก ควรตั้งรูปแบบเดียวกันและมีโลโก้เดียวกันincludes/header.php + appearance.phpต่ำ

P1 · วิธีรับธีมจากระบบหลัก (แนวทาง)

ระบบหลัก inject ตัวแปรธีมใน includes/layout.php อยู่แล้ว (<style id="theme-vars">:root{...}</style> อ่านจากตาราง site_settings) — parts เชื่อมฐานข้อมูลหลักได้อยู่แล้วผ่าน bridge ที่เพิ่งทำ จึงทำแบบเดียวกันได้เลย:

// parts/includes/header.php — อ่านธีมจาก site_settings ของระบบหลัก แล้ว map ลง token เดิมของ parts <style id="theme-vars"> :root{ --primary: <?= h(main_setting('color_primary','#2563eb')) ?>; --primary-dark: <?= h(main_setting('color_primary_dark','#1d4ed8')) ?>; --sidebar: <?= h(main_setting('color_sidebar','#1e293b')) ?>; --bg: <?= h(main_setting('color_page_bg','#f1f5f9')) ?>; --app-font: <?= h(main_setting('font_family',"'Noto Sans Thai','Segoe UI',sans-serif")) ?>; } </style>

token ที่เหลือของ parts (shadow, radius, success/warning/danger) คงไว้ตามเดิม — เป็นชุดที่ดีอยู่แล้ว และจะถูกยกไปให้ระบบหลักใช้ด้วยใน Part 4

Part 4Design Token กลาง + ลำดับการลงมือ

4.1 ชุด token กลางที่เสนอ (ใช้ทั้ง 2 ระบบ)

/* ==== โครง token กลาง — สีมาจากธีม appearance.php, โครงสร้างมาจาก parts ==== */ :root{ /* จากธีม (เปลี่ยนได้จาก appearance.php — sync ทั้ง 2 ระบบ) */ --primary:#e11d74; --primary-dark:#b3155c; --sidebar-bg:#4e2985; --sidebar-active:#e11d74; --page-bg:#f1ecfe; --app-font:'Noto Sans Thai','Segoe UI',sans-serif; /* สีสถานะ — ความหมายเดียวกันทั้ง 2 ระบบ */ --success:#16a34a; --success-soft:#dcfce7; --info:#1d4ed8; --info-soft:#dbeafe; --warning:#a16207; --warning-soft:#fef9c3; --danger:#b91c1c; --danger-soft:#fee2e2; /* โครงสร้าง (เดิมของ parts — ยกให้ระบบหลักใช้ด้วย) */ --radius:12px; --radius-sm:8px; --shadow-sm:0 1px 2px rgba(15,23,42,.06); --shadow-md:0 4px 16px rgba(15,23,42,.08); --input-h:40px; --transition:.18s ease; /* Type scale เดียวกัน */ --fs-body:15px; --fs-h1:22px; --fs-table:13.5px; --fs-badge:12px; }
