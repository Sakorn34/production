# ADR 0001 — เปลี่ยนไปใช้ SSO ภายนอกแทนระบบ login/role เดิม

- **สถานะ:** Accepted (ใช้งานจริงในปัจจุบัน)
- **ขอบเขต:** `finishgoogs_ma_update/` เท่านั้น (`parts/` ไม่มีระบบ auth ของตัวเอง)

## บริบท

เดิมระบบทะเบียนเครื่องและซ่อมบำรุงมีระบบ login/role ภายในของตัวเอง (ตาราง `users`, ระบบสิทธิ์แยกระดับ) ปัจจุบันโค้ดยืนยันชัดเจนว่า**เลิกใช้แล้ว**:

- `finishgoogs_ma_update/login.php` ไม่มีฟอร์ม login อีกต่อไป มีแค่ `header('Location: ' . SSO_LOGIN_URL); exit;`
- `finishgoogs_ma_update/users.php` เป็นเพียงหน้า redirect กลับหน้าแรก พร้อมคอมเมนต์ "เลิกใช้ระบบผู้ใช้งานภายในแล้ว"
- คอมเมนต์ใน `config.php` บรรทัด 195: `// ---------- auth (session profile เท่านั้น — ไม่ใช้ตาราง users / role / login ภายใน) ----------`

องค์กรมีระบบ SSO กลาง (`bit-online.net`) ที่ใช้ร่วมกันหลายระบบอยู่แล้ว การดูแล login/role ซ้ำในแต่ละระบบทำให้ต้อง sync บัญชีผู้ใช้/สิทธิ์หลายที่ และเสี่ยงข้อมูลไม่ตรงกัน

## การตัดสินใจ

1. **ล็อกอินทั้งหมดผ่าน SSO ภายนอก** — `SSO_LOGIN_URL = 'https://bit-online.net/bitlogin/bitlink.php'` (`config.php:196`) ทุก request ที่ไม่มี session profile จะถูก `require_login()` (`config.php:261`) redirect ไปที่นี่
2. **ไม่มีระดับสิทธิ์ผู้ใช้แบบเดิมอีกแล้ว** — ฟังก์ชัน `can($perm)` (`config.php:279`) รับพารามิเตอร์ชื่อสิทธิ์ไว้เพื่อความเข้ากันได้กับโค้ดเดิมที่เรียกมัน แต่**คืนค่า true เสมอ**ถ้ามี session profile ไม่ตรวจ `$perm` จริง — ทุกคนที่ผ่าน SSO ใช้งานฟีเจอร์หลักได้เท่ากันหมด
3. **อ่านข้อมูลผู้ใช้จาก `$_SESSION['profile']`** ที่ SSO เซ็ตให้ ผ่าน compatibility layer `includes/session_profile.php` (ฟังก์ชันขึ้นต้น `maintenance_*` และ `ss_*` — สืบทอดชื่อจากระบบเดิมชื่อ "maintenance" ที่เคยใช้ SSO นี้มาก่อน) ชื่อที่ใช้บันทึกลง audit log ทุกจุดคือ `login_name` จาก profile (เช่น `Tom`)
4. **ข้อยกเว้นเดียว:** หน้า "ระบบหลังบ้าน" (ตั้งค่า/ปรับแต่งหน้าตา และ action ที่กระทบข้อมูลส่วนกลางอย่าง sync ทั้งหมด) ยังคงต้องปลดล็อกเพิ่มด้วย PIN แบบ hardcode (`9981`) หรือ `login_name === 'Tom'` — ดู `settings_admin_unlocked()` (`config.php:246`) และ `includes/settings_gate.php`

## ผลกระทบ

- ไม่มี mechanism ปฏิเสธผู้ใช้บางคนไม่ให้เข้าฟีเจอร์หลักของระบบได้อีกแล้ว (นอกจากหน้าหลังบ้าน) — ถ้าต้องแบ่งสิทธิ์ละเอียดกว่านี้ในอนาคต ต้องออกแบบระบบ role ใหม่ทั้งหมด เพราะ `can()` ปัจจุบันไม่รองรับ
- การพึ่งพา `login_name === 'Tom'` แบบ hardcode เป็นจุดเปราะ — ถ้าชื่อ login เปลี่ยนหรือมีแอดมินคนใหม่ ต้องแก้โค้ดตรงนี้โดยตรง ไม่มีหน้าจัดการแอดมิน
- ระบบ `parts/` ไม่ได้ใช้แนวทางเดียวกันนี้ (ไม่มี auth เลย) — ควรพิจารณาว่าจะทำให้สอดคล้องกันหรือไม่หากเปิดให้เข้าถึงจากนอกเครือข่ายภายใน
