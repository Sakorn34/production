เส้นทางที่ 1 — sync ทะเบียนสินค้า

ทุกครั้งที่บันทึกหรือแก้ไขเครื่องผลิตใหม่ ระบบทะเบียนเครื่องจะเขียนสำเนาเข้า biton_stockparts.stock ให้อัตโนมัติ ตารางนี้เป็นของทีมสต็อกอะไหล่ ฝั่งทะเบียนเครื่องห้ามแก้โครงสร้างตาราง ทำได้แค่อ่าน/เขียนแถวข้อมูล ถ้า sync คลาดเคลื่อนมีหน้าเทียบข้อมูลย้อนหลังให้แก้ด้วยมือ

เส้นทางที่ 2 — webhook ตัดสต็อกอะไหล่

เมื่อมีการเบิกใช้อะไหล่ผูกกับเครื่อง ฝั่งทะเบียนเครื่องเป็นผู้ยิง request ออกไปเอง ไปยัง endpoint ของระบบสต็อกอะไหล่ เพื่อตัดยอดให้อัตโนมัติ โดยไม่ต้องเข้าไปเบิกผ่านหน้าเว็บสต็อกอะไหล่เลย

เหตุผลเชิงระบบที่ควรรู้ก่อนแก้โค้ด

สรุปจากบันทึกการตัดสินใจ (ADR) เต็มอยู่ที่ docs/adr/

ADR 0001

ล็อกอินผ่าน SSO ภายนอกเท่านั้น

เลิกใช้ระบบ login/role ภายในทั้งหมด เพื่อไม่ต้องดูแลบัญชีผู้ใช้ซ้ำกับระบบอื่นในองค์กร

ข้อยกเว้น: หน้าตั้งค่า/ปรับแต่งหน้าตา ยังล็อกด้วย PIN เพิ่มอีกชั้น
ADR 0002

ทะเบียนสินค้ามีจุดเดียว

ยกเลิกตารางสำเนาที่เคยมี (shared_assets) เหลือ biton_stockparts.stock เป็นแหล่งเดียว กันข้อมูลสองชุดไม่ตรงกัน

ผลคือ: ฝั่งทะเบียนเครื่อง “ฝาก” ข้อมูลไว้ในตารางของทีมอื่น ไม่ใช่เจ้าของ schema
ADR 0003

ล็อกธุรกรรมกันข้อมูลหายเงียบ

เคยเกิดเหตุจริง: บันทึกสำเร็จบนหน้าจอ แต่ข้อมูลหายเพราะ autocommit ปิดอยู่โดยไม่รู้ตัว แก้ด้วยการบังคับ autocommit และใช้ GET_LOCK ตอนออกเลขรันนิ่ง

สำคัญ: connection ใหม่ในอนาคตต้องบังคับ autocommit เช่นกัน
